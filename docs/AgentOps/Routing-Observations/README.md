## 誰做什麼

原 Codex 開發 thread：正常分派、執行、驗證與必要失敗處理；在既有自然 checkpoint 或交接時，摘記已有事實及輕量分類。

外部 reviewer：由使用者發起後，讀取這個目錄與當時政策版本，必要時沿證據定位查相關 Git 差異；負責跨案例比較、判斷不確定性與提出政策調整。

觀測是既有開發的旁路紀錄，隨自然工作產生。產品優先序、工作顆粒度、驗收與 Goal 由產品流程管理；樣本不足時保留未知，照常推進產品。

## 何時與寫在哪裡

已委派、有重要交接／重做，或已實質考慮委派但選擇原 owner 延續時，在 [Observations.md](Observations.md) 追加一筆。每個自然 checkpoint 可合併同一事件的更新，避免每個 tool call 另記一筆。

直接沿用當時已有的命令、測試及 runtime 結果；沒有數值就記未量測，沒有實際模型證據就記未知。原始紀錄留既有適當忽略區。公開紀錄只放去識別的工作描述及安全定位；本地私人檔案內容、credentials、畫面原文與整段 session log 不上 Git。

Root 是唯一彙整／寫入者，worker 透過原有 handoff 提供資料。避免多個 agents 同時修改觀測檔。

## 一筆最小紀錄

```text
### <時間＋簡短事件名稱>
任務／政策：一句話；當時 policy 版本；base commit 或既有證據定位。
配置：Root；要求的 child model／effort → 實際值；實際值的 metadata 來源或未知。
Context：起始 affinity 高／部分／低；額外重載低／中／高或未知。
核對：handoff＋Root 核對低／中／高；僅異常時加一句實際動作。
返工／人工：次數或未知；必要時標工具、context、推理、需求變更等可直接確認的原因。
結果：合格／部分／受阻／失敗；對應產品證據定位。
可選量測：既有執行／等待／前台時間或逐任務用量；未量測即略過。
```

以上只是格式，不是觀測案例。套用包本身不產生模型效果樣本。

政策版本與實際模型是歸因前提。若實際 metadata 不可取得，保留要求值但標示實際未知，外部 review 不將它算成已確認的模型樣本。

## 分類與時間的含義

核對成本的低／中／高是粗略工作量 proxy，不是帳單：低＝少量 diff／定位證據；中＝必要接縫審查與針對性重驗；高＝因證據不足而大量重查或接回。高風險任務的必要驗證另註其理由，不能僅因核對多就判失敗。

返工是為修正錯誤而重做；正常整合驗證不算返工。無法確認原因時記未知，不要求當場為 routing 歸因另作調查。人工介入只記發生的校正、接管或額外打斷；產品本來需要的主觀接受分開描述。

可取得時間時，分開記執行、工具等待及前台占用；並行區間不直接相加當成完成時間。沒有逐任務用量時，帳戶百分比差值僅是共享快照，不能換算單個 worker 費用。

## 保存與外部評估

觀測可隨正常產品 commit 一起提交，檔案責任仍獨立；它不承載產品 Exact next step 或恢復狀態。沒有產品 commit 時，可在下一個正常 checkpoint 補記，不為補欄位延遲產品交付。

使用 base commit、已存在的產品 commit 或相對證據定位即可；與程式同次提交的觀測，以 Git 查包含該筆的 commit，不為在檔內嵌入自身 commit SHA 而循環 amend。更新觀測檔時保留已有事件與來源。

外部評估先辨別 task class、context、驗證風險與資料完整性，再比較返工、核對、等待及人工介入。自然觀察可發現明顯浪費，不能單靠不同任務的時間宣稱精確省費比例或因果優勢。證據不足就保留未知。

評估結果由外部 reviewer 回報使用者。當下開發不需要為每筆事件寫「模型是否划算」的結論，也不自行更改全域路由政策；必要的當次升級／接回仍按現行 routing policy 執行。
