# Phase 2 validation evidence

## M2 — Workspace navigation foundation (2026-09-27)

Production build passes; 94 unit/integration/browser-adapter tests and 14 production E2E pass. Tests construct a real schema-1 database independently and verify validated backup, schema upgrade, failure leaving original bytes intact, hierarchy cycles/collisions/stale revisions, atomic subtree recovery, exchange v2 and old v1 compatibility. Browser coverage adds 3,000 notes (2,275 siblings, six levels), bounded 80-row lists, search, quick switch, heading links, move preserving note identity, create/delete and actual host restart. Three regression scenarios cover same-DB multi-tab clean refresh, dirty stale-base rejection with draft retention, and rejection of outdated search offsets. Per-note editor undo/selection is cached for the latest 20 documents; external replacements discard incompatible undo.

Personally used the in-app browser on an ignored synthetic 1,200+ note database: opened the upgraded app, created a folder/note, wrote Markdown and nested values, searched a late note, inspected missing links, followed a heading link, and moved a note to root. Filter reset revealed the moved/new active note; metadata-only navigation displayed zero value recalculations. The existing default user workspace was not opened by the new host.

`benchmarks/navigation-browser.json` records real production search input-to-visible-result samples with automation overhead. Synthetic source: 3,000 notes, 2,275 siblings, six folder levels. The first isolated run ranged 19–30 ms; subsequent full-suite measurements are retained in the JSON. Domain link workload: 3,000 notes / 9,000 links, cold index 68.56 ms and parser-cache reuse 17.36 ms (Node, not DOM timing). Link resolution still scans the index; the UI builds it lazily and reuses unchanged parsing. The original high-reference E2E workload also passes.

Known boundaries: folder names are distinct from computed-value namespaces. Literal path links can become unresolved after moves/renames and are reported; this milestone does not rewrite them silently. Nested heading fragments, asset fragments and local query parameters are preserved but marked unsupported. Titles unsuitable for logical paths are diagnosed by the link index. Attachments and mirror are later checkpoints. The records and identifier list caps are addressed next in M3.

## M3 — Knowledge and structured-data management (2026-09-27)

Production build, 128 tests and 16 production E2E pass before the final storage-limit preview guard. Identifier/reference/diagnostic lists are now fully paginated and searchable by name, namespace, source and status. Details retain all duplicate definition locations, direct dependencies/dependents and transitive impact. The semantic rename adapter exposes owner-aware source spans; preview/apply is a 30-minute, single-use server-held plan bound to workspace/revision, with atomic recovery and rollback. Literal prose/code and unrelated JSON escapes remain unchanged. Tests cover dotted record ownership, missing-reference repair, collisions, new/existing cycles and 12,000-node chains/cycles. A measured 12,000-node impact calculation took 143 ms in the isolated domain run.

Records now have paginated collection browsing, raw/resolved-value search, exact field filtering, sorting, full field detail and reference insertion/navigation. A 10,000-record fixture exercises the standalone browser; production tests search/edit a late record among 500, follow a table row, open all results beyond its 200-row inline limit, and preserve a 250-result filter. Existing names/field keys use reviewed rename; normal field-value edits stay direct. Recovery preview names the whole-workspace scope and enumerates changed notes/folders/records before applying the reviewed revision.

Personally used the app to rename `daily.name` to `daily.person`, reviewed the exact declaration/dependency diff, confirmed the nested greeting stayed reactive, found/edited a record beyond the former 150-row cap, reviewed both note and record changes in recovery, and restored the workspace. Cosmetic recent-note persistence is deferred while a review dialog is open so it cannot invalidate that review.

Deliberate limits: a record move across ambiguous dotted ownership is rejected. Collection/filtered-field renames that would silently break an existing `grasp-query` are blocked with locations; change those explicit queries first. Query source is not silently rewritten. The value language remains provisional string interpolation. File/mirror/rebuild and real migration rehearsal are still pending M4/M5.

Final M3 validation: build and all 129 tests pass, including host storage-limit preview rejection (no token for invalid projected content); the 16 production E2E remain green.

## M4 — Visible files, attachments and Markdown fallback (2026-09-27)

Production build, all 159 tests and 19 production E2E pass. Schema 3 stores immutable, SHA-256-verified attachment BLOBs in SQLite; known v1/v2 upgrades create a validated backup. Recovery preserves asset bytes and its UI previews attachment changes. Raster assets render in Live Preview; other files download without executing HTML/SVG. Canonical asset links and resolved relative/wiki embeds use the editor adapter without changing source or undo history.

The Files panel exposes inbox, outbox, attachment metadata, actual paths, copy/download/open-folder, multi-file input/drop and AI return review. Export saves a real outbox file before download. AI folder export contains readable notes, records metadata, assets and a verified reconstruction manifest. Inbox writes never import implicitly. Tests cover 500-entry pagination, workspace-isolated pending text, asynchronous close/failure and visible busy feedback.

Persistent mirror publishes immutable payload revisions and complete manifest/index pairs asynchronously. External edits remain preserved and are reported; database save succeeds even when the file root is blocked, and explicit retry repairs the projection later. Tests cover traversal, reserved paths, symlinks, checksum damage, incomplete publication, deep/colliding names, restart and shutdown/switch while an export is using the old DB. New-database rebuild verifies all bytes, keeps entity IDs/timestamps, creates a fresh workspace ID, and refuses existing destinations. A production test starts from a damaged DB, confirms the launcher/recovery UI remains available and original bytes remain untouched.

Production UI E2E uploads two assets, inserts/loads a PNG, downloads saved exchange, reviews/applies AI-return Markdown, exports a real folder, edits mirror externally, preserves that edit during refresh, rebuilds and restarts the host, and verifies notes/assets. Root personally used inbox review/apply and AI-folder export on the separate 1,204-note synthetic workspace and inspected its displayed physical paths. Import preview now counts actual record changes rather than describing all preserved records as imported.

The first parallel full test attempt exposed shared Vite optimizer-cache collisions and a performance sample distorted by simultaneous browser/benchmark runs. Each browser harness now uses its own cache with HMR/watch disabled. Final isolated full suite passes without relaxing the original 1,500 ms editor budget. See `FILES-PERFORMANCE.md`: 2,820-note cold mirror 2.54 s, AI folder 2.24 s, one-note mirror update 674 ms with one payload written and 2,820 reused; full verified rebuild read 4.43 s. Projection timings are not typing latency.

Limits: no automatic revision pruning; each mirror update still scans file metadata and writes the complete index/manifest. Controlled single-file Markdown exchange preserves existing attachments, while complete cross-workspace transfer/rebuild uses the folder manifest and bytes. Real private MainVault rehearsal remains M5.
